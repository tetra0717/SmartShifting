# SmartShifting / Glint

モニター上の対象ごとに異なる光・色の揺らぎを重ね、スマホの背面カメラで対象IDを読み取ります。Glintを使ったゲーム開発のベースです。

## 起動

PCに [Node.js](https://nodejs.org/en/download) 22以上（24 LTS推奨）とGitを入れて、次のコマンドを実行します。Windows・macOS・Linuxで同じ手順です。

```sh
git clone https://github.com/tetra0717/SmartShifting.git
cd SmartShifting
npm ci
npm start
```

初回は、このPC用のHTTPS証明書と `logs/` を自動生成します。OpenSSLのインストールやビルドは不要です。次回からは `npm start` だけで起動できます。終了はターミナルで Ctrl+C です。

1. PCで `http://localhost:8080/` を1タブだけ開きます。従来の `/glint` も同じ画面です。
2. PC画面の「初回のスマホ接続ガイド」を開き、同じWi-Fiのスマホで表示されたガイドURLを開きます。初回だけ証明書をスマホへ登録します。
3. ガイドに表示された `https://PCのLANアドレス:8443/phone` をスマホで開きます。`/glint-phone` も使えます。
4. スマホのカメラを起動します。PCを全画面にし、Hキーで操作パネルを隠します。
5. 背面レンズを対象に近づけ、静止させます。識別すると両画面に対象名が出て、PCのアイコンが反応します。

既定は実機で成功した **6対象・強さ0.8・動く模様** です。変更や診断は「開発・診断」を開きます。設定はサーバー再起動で既定に戻ります。

## 接続できないとき

- スマホのブラウザでカメラを使うにはHTTPSが必要です（[ブラウザAPIの仕様](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia#privacy_and_security)）。証明書はそのHTTPS接続のために使います。
- 証明書と秘密鍵はPCごとに `.certs/` へ生成し、GitHubへ送信しません。スマホ側の初回登録は [接続ガイド](http://localhost:8080/setup) に沿って行います。OSの信頼設定を自動変更することはありません。
- 既存の有効な証明書は再利用します。独自の証明書を使う場合は `TLS_CERT` と `TLS_KEY`、公開HTTPSへの接続先は `PUBLIC_URL` で指定できます。
- URLへ接続できない場合は同じネットワークか、OSの通信許可やファイアウォールを確認してください。
- ポート使用中のエラーが出る場合は、前に起動したサーバーを終了します。既定ポートは8080と8443です。
- Windows PowerShellで `npm.ps1` の実行が禁止されている場合は、`npm.cmd ci` / `npm.cmd start` を使います。
- PC表示は1タブにし、モニター側の画面を前面に置きます。カメラを再取得するときは「再取得」、終了時は「停止」を押します。ページを更新した場合は両方を読み直してください。
- 未確定が続く場合は、境界・操作パネルを避け、標準設定に戻して試してください。

## ログと確認

- サーバーは接続・切断・設定変更・対象状態の変化・エラーをターミナルと `logs/glint.jsonl` に自動保存します。1ファイル約5MiB、過去3世代まで保持します。
- ブラウザのエラーもコンソールとサーバーへ記録します。通信障害中はブラウザ側の診断ログを保存してください。
- PC・スマホそれぞれの「開発・診断」→「診断ログを保存」でJSONを保存できます。詳細なRGB・表示履歴はチェックを入れた間だけメモリに記録します。PCは直近24回、スマホは直近1800フレームまでです。
- サーバーはカメラ画像や毎フレームのRGBをディスクへ保存しません。スマホからPCへ送るのは平均RGB・飽和率です。手動保存した詳細ログにはそれらの統計や表示素材の色履歴が含まれます。

```powershell
npm run check
npm test
```

`http://localhost:8080/api/health` でサーバーとPC表示の接続状態を確認できます。

GitHub ActionsでもWindows・macOS・Linux、Node.js 22・24で同じチェックを実行します。

## ゲームを作る

ゲームの反応は `public/game.js` から追加します。`glint:acquired` / `glint:released` イベントで端末IDと対象IDを受け取れます。詳細は [開発メモ](docs/development.md) を参照してください。

識別できるのは対象IDです。物理的な接触、対象内の座標、スマホ本体の位置は測りません。「再確認中」は新しい確定ではありません。機種や素材が変わった場合の取得時間・識別性能は実機で確認してください。
